# 4. 결과 & 배운 점

## 결과

| 항목 | 내용 |
|------|------|
| 완성 범위 | 로그인 → 로비 → 가챠 → 스테이지 선택 → 전투 → 보상 결과 → 운영툴 E2E 플레이 가능 |
| 개발 규모 | Unity 클라이언트 + ASP.NET 웹서버 + ASP.NET MVC 운영툴 1인 전담 |
| 운영 | AWS EC2 + Docker + CloudFront 실서버 배포 및 운영 |

---

## 배운 점

### 1. 클라이언트-서버 통신

서버가 전투 로직을 전담하고 클라이언트는 결과를 받아 연출하는 구조를 직접 설계하면서, 클라이언트와 서버가 어떤 데이터를 주고받는지 실전으로 익혔다. API 설계부터 Protobuf 직렬화, 응답 처리까지 전 과정을 경험했다.

### 2. Unity 씬 구조 설계

단일 LobbyScene에서 팝업으로 화면을 관리하고, 3D 오브젝트가 필요한 전투·가챠만 Additive 씬으로 분리하는 구조를 직접 설계했다. 씬 전환 없는 빠른 화면 이동과 메모리 효율을 동시에 얻으면서, 설계 결정이 실제 플레이 경험에 어떻게 영향을 주는지 체감했다.

### 3. 운영툴을 통한 실제 운영 경험

콘텐츠 관리, 전투 밸런스 시뮬레이터, 유저 계정 조회까지 갖춘 운영툴을 직접 만들고 사용하면서, 게임 서비스가 단순히 클라이언트-서버로 끝나지 않는다는 것을 알게 됐다. 밸런스 수치를 바꾸고 시뮬레이터로 즉시 검증하는 과정이 개발 속도를 크게 높였다.

### 4. 클라이언트부터 배포까지 전 과정 경험

Unity 클라이언트, ASP.NET 서버, 운영툴, AWS EC2 배포까지 혼자 담당하면서 각 레이어가 어떻게 연결되는지 구조적으로 파악하게 됐다. 팀 개발 환경에서 클라이언트 포지션으로 일하더라도 서버·인프라 팀과 구체적으로 소통할 수 있다는 자신감을 얻었다.
