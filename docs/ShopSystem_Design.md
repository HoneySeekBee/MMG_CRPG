## 1. 개요

### 1.1 목적
유저가 게임 내 재화(골드, 젬, 토큰 등)를 사용하여 아이템을 구매할 수 있는 상점 시스템.

### 1.2 상점 유형

| 유형 | 설명 | 예시 |
|------|------|------|
| **일반 상점** | 상시 운영, 고정 상품 목록 | 장비 상점, 소모품 상점 |
| **기간 한정 상점** | 운영 기간이 있는 이벤트 상점 | 설날 이벤트 상점, 주간 특가 |

### 1.3 핵심 규칙
- 가격 검증, 재화 차감, 아이템 지급은 모두 서버에서 처리한다
- 상품별로 서로 다른 재화(골드, 젬, 토큰 등)로 가격을 설정할 수 있다
- 상품별로 유저당 일일/주간/총 구매 횟수를 제한할 수 있다
- 동일 유저의 동시 구매 요청을 방지한다

## 2. 데이터 모델

### 2.1 관계도

```
상점 (1) ──── (N) 상품 (N) ──── (1) 아이템
                    │
                    └──── (N) 구매 기록
```

### 2.2 상점

| 필드 | 타입 | 설명 |
|------|------|------|
| ID | 정수 (PK) | 상점 ID |
| 코드 | 문자열 (UNIQUE) | 상점 코드 (예: `GENERAL_EQUIP`, `EVENT_2026_LUNAR`) |
| 이름 | 문자열 | 상점명 |
| 상점 유형 | 열거형 | 일반 / 기간 한정 |
| 운영 시작일 | 일시 (nullable) | 기간 한정 상점의 시작일. 일반 상점은 비어있음 |
| 운영 종료일 | 일시 (nullable) | 기간 한정 상점의 종료일. 일반 상점은 비어있음 |
| 활성 여부 | 불리언 | 운영자가 상점을 노출/숨김 처리 |
| 표시 순서 | 정수 | 클라이언트에서의 상점 정렬 순서 |

### 2.3 상품

| 필드 | 타입 | 설명 |
|------|------|------|
| ID | 정수 (PK) | 상품 ID |
| 소속 상점 | FK → 상점 | 이 상품이 속한 상점 |
| 판매 아이템 | FK → 아이템 | 구매 시 지급되는 아이템 |
| 결제 재화 | FK → 재화 | 가격에 사용되는 재화 종류 |
| 가격 | 정수 | 1회 구매 가격 |
| 1회 지급 수량 | 정수 | 한 번 구매 시 지급되는 아이템 수 (기본 1) |
| 일일 구매 제한 | 정수 (nullable) | 하루 최대 구매 횟수. 비어있으면 무제한 |
| 주간 구매 제한 | 정수 (nullable) | 일주일 최대 구매 횟수. 비어있으면 무제한 |
| 총 구매 제한 | 정수 (nullable) | 통산 최대 구매 횟수. 비어있으면 무제한 |
| 표시 순서 | 정수 | 상점 내 상품 정렬 순서 |
| 활성 여부 | 불리언 | 운영자가 상품을 노출/숨김 처리 |

### 2.4 구매 기록

| 필드 | 타입 | 설명 |
|------|------|------|
| ID | 정수 (PK) | 기록 ID |
| 유저 | FK → 유저 | 구매한 유저 |
| 구매 상품 | FK → 상품 | 구매한 상품 |
| 수량 | 정수 | 구매 수량 |
| 지불 금액 | 정수 | 실제 지불한 금액 |
| 결제 재화 코드 | 문자열 | 결제에 사용된 재화 코드 |
| 구매 시각 | 일시 | 구매가 완료된 시각 |

## 3. 구매 플로우

### 3.1 유저 흐름

1. 유저가 상점 목록을 열면, 활성 상점과 상품 목록을 확인할 수 있다
2. 각 상품에는 가격, 잔여 구매 횟수가 표시된다
3. 유저가 상품을 선택하고 구매 버튼을 누른다
4. 서버에서 검증 후, 성공하면 재화가 차감되고 아이템이 지급된다
5. 실패하면 적절한 에러 메시지를 표시한다

### 3.2 서버 검증 순서

| 순서 | 검증 항목 | 실패 시 |
|------|----------|---------|
| 1 | 상점이 존재하는가 | `SHOP_NOT_FOUND` |
| 2 | 상점이 활성 상태인가 | `SHOP_NOT_ACTIVE` |
| 3 | 기간 한정 상점이면 운영 기간 내인가 | `SHOP_NOT_IN_PERIOD` |
| 4 | 상품이 존재하는가 | `PRODUCT_NOT_FOUND` |
| 5 | 상품이 활성 상태인가 | `PRODUCT_NOT_ACTIVE` |
| 6 | 일일 구매 제한을 초과하지 않는가 | `DAILY_LIMIT_EXCEEDED` |
| 7 | 주간 구매 제한을 초과하지 않는가 | `WEEKLY_LIMIT_EXCEEDED` |
| 8 | 총 구매 제한을 초과하지 않는가 | `TOTAL_LIMIT_EXCEEDED` |
| 9 | 재화 잔액이 충분한가 | `INSUFFICIENT_CURRENCY` |

### 3.3 구매 성공 시 처리
- 재화 차감
- 아이템 지급
- 구매 기록 저장
- 위 3가지는 하나라도 실패하면 전부 취소 (원자적 처리)

### 3.4 동시 구매 방지
- 동일 유저가 동시에 구매 요청을 보낼 경우, 먼저 도착한 요청만 처리
- 뒤늦은 요청은 `PURCHASE_IN_PROGRESS` 에러 반환

## 4. 구매 제한 규칙

### 4.1 기간 기준

| 제한 유형 | 기간 | 리셋 시점 |
|----------|------|----------|
| 일일 | UTC 00:00 ~ 23:59 | 매일 UTC 00:00 |
| 주간 | 월요일 UTC 00:00 ~ 일요일 UTC 23:59 | 매주 월요일 UTC 00:00 |
| 총 | 제한 없음 | 리셋 없음 |

### 4.2 예시

> 상품 A: 일일 3회, 주간 10회, 총 50회 제한
>
> - 월요일에 3번 구매 → 화요일에 다시 3번 가능
> - 한 주에 10번 구매하면 → 다음 월요일까지 구매 불가
> - 통산 50번 구매하면 → 이후 영구 구매 불가

## 5. API 엔드포인트

### 5.1 게임 클라이언트용

| Method | 경로 | 설명 |
|--------|------|------|
| GET | `/api/pb/shop` | 활성 상점 + 상품 목록 (유저별 잔여 구매 횟수 포함) |
| GET | `/api/pb/shop/{shopId}` | 특정 상점 상세 |
| POST | `/api/pb/shop/purchase` | 상품 구매 |

### 5.2 운영툴용

| Method | 경로 | 설명 |
|--------|------|------|
| GET | `/api/shop` | 상점 목록 (페이징, 필터) |
| GET | `/api/shop/{id}` | 상점 상세 |
| POST | `/api/shop` | 상점 생성 |
| PUT | `/api/shop/{id}` | 상점 수정 |
| DELETE | `/api/shop/{id}` | 상점 삭제 |
| GET | `/api/shop/{shopId}/products` | 상품 목록 |
| POST | `/api/shop/{shopId}/products` | 상품 추가 |
| PUT | `/api/shop/{shopId}/products/{productId}` | 상품 수정 |
| DELETE | `/api/shop/{shopId}/products/{productId}` | 상품 삭제 |
| GET | `/api/shop/purchase-logs` | 구매 기록 조회 |

### 5.3 구매 요청/응답

**요청**
| 필드 | 설명 |
|------|------|
| 상품 ID | 구매할 상품 |
| 수량 | 구매 수량 (보통 1) |

**응답 (성공)**
| 필드 | 설명 |
|------|------|
| 성공 여부 | true |
| 구매 후 잔액 | 재화 차감 후 남은 금액 |
| 아이템 보유 수량 | 지급 후 총 보유 수량 |
| 일일 구매 횟수 | 갱신된 오늘 구매 횟수 |
| 주간 구매 횟수 | 갱신된 이번주 구매 횟수 |
| 총 구매 횟수 | 갱신된 통산 구매 횟수 |

**응답 (실패)**
| 필드 | 설명 |
|------|------|
| 성공 여부 | false |
| 에러 코드 | 3.2절의 에러 코드 중 하나 |

## 6. 운영툴 요구사항

### 6.1 상점 관리

| 페이지 | 기능 |
|--------|------|
| 상점 목록 | 유형별/활성별 필터, 이름·코드 검색, 페이징 |
| 상점 생성 | 코드, 이름, 유형, 기간(기간 한정일 때만), 활성 여부 입력 |
| 상점 수정 | 상점 정보 수정 + 하단에 소속 상품 목록 관리 |

### 6.2 상품 관리

| 기능 | 설명 |
|------|------|
| 상품 추가 | 아이템 선택, 결제 재화 선택, 가격, 지급 수량, 구매 제한 설정 |
| 상품 수정 | 위 항목 변경 |
| 상품 삭제 | 상품 제거 |

### 6.3 구매 기록 조회

| 기능 | 설명 |
|------|------|
| 검색 | 유저 ID, 상품 ID, 기간으로 필터링 |
| 표시 정보 | 유저, 상품명, 수량, 지불 금액, 재화, 구매 시각 |

## 7. 클라이언트 표시 정보

### 7.1 상점 목록 화면

각 상점에 표시할 정보:
- 상점 이름
- 상점 유형 (일반 / 기간 한정)
- 기간 한정인 경우 남은 시간

### 7.2 상품 목록 화면

각 상품에 표시할 정보:
- 아이템 아이콘, 이름, 등급
- 결제 재화 종류 + 가격
- 1회 지급 수량
- 구매 제한이 있는 경우: 잔여 횟수 (예: `2/3`)
- 구매 제한을 모두 소진한 경우: "매진" 표시
